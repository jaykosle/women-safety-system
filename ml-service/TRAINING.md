# Risk-prediction model — training guide

The `/predict-risk` endpoint is served by a pair of XGBoost models trained on
the NCRB district crime data joined with the project's synthetic geocoded
crime records.

## Quick retrain (one command)

```powershell
# from project root
python ml-service/train_risk_model.py
```

Takes ~30 seconds on a laptop CPU. Re-run any time the underlying data changes.

## What the script does

1. Loads `risk_zones.csv` (219k geocoded rows, target = `riskScore`).
2. Builds a district centroid index from `synthetic_crime_data.csv` (~1,090 centroids).
3. Loads NCRB district aggregates from
   `Datasets/Crimes in india/crime/42_District_wise_crimes_committed_against_women_2014.csv`.
4. Assigns each risk-zone point to its nearest district and joins district-level
   crime totals + composition fractions.
5. Trains two models:
   - `risk_model.json` — XGBRegressor predicting the continuous risk score (0–100).
   - `risk_classifier.json` — XGBClassifier predicting LOW / MEDIUM / HIGH / CRITICAL.
6. Saves lookup tables `district_centroids.csv` and `district_ncrb.csv` so
   `main.py` can compute the same features at inference time with no extra deps.
7. Writes `risk_model_meta.json` with feature list + held-out test metrics,
   plus `feature_importance.csv` for inspection.

## Current metrics (held-out 20% test split, ~44k rows)

| Model | Metric | Value |
|---|---|---|
| Regressor | MAE | 6.42 |
| Regressor | R² | 0.936 |
| Classifier | Accuracy | 0.856 |

## Why this isn't a tautology

`risk_zones.csv` was originally generated by the formula
`riskScore = 1.5 × severityScore × crimeCount`. We deliberately **exclude
`severityScore`** from the feature set so the model can't memorise the formula.
The features that are used (`crimeDensity`, `crimeCount`, `nightCrimeRate`,
plus the NCRB district context) are the same kind of inputs a real model would
compute from raw incidents — they describe *what's happening* near the point,
not the formula that generated the label. The remaining R² gap (0.064) reflects
the spatial variation the model genuinely had to learn.

## Inference path

`ml-service/main.py` loads the four artifact files at FastAPI startup. The
`/predict-risk` endpoint:

1. Queries Postgres `crime_records` within a 0.003° radius (≈330 m).
2. Computes `crimeDensity`, `crimeCount`, `nightCrimeRate` from those rows.
3. Finds the nearest district from `district_centroids.csv`.
4. Looks up the district's NCRB context from `district_ncrb.csv`.
5. Calls `model.predict()` and returns the score + level.

If any artifact file is missing (e.g. first-time setup), the endpoint
automatically falls back to the original hand-tuned heuristic so the API never
hard-fails.

## `/predict-risk-detailed`

Same inputs, richer response — class probabilities and the top-5 features
contributing to the prediction (via XGBoost SHAP-style `pred_contribs`). Useful
for an "explain why" UI tooltip on the dashboard.

## Adding new training data

When you have updated NCRB data for a more recent year (the file naming
convention is `42_District_wise_crimes_committed_against_women_<year>.csv`):

1. Drop it into `Datasets/Crimes in india/crime/`.
2. Edit `NCRB_2014` constant near the top of `train_risk_model.py` to point at
   the new file (or change the script to load multiple years and use `year_filled`
   as a real feature instead of a constant).
3. Re-run `python ml-service/train_risk_model.py`.
